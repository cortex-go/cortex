# CX02 evidence - authentication lifecycle

Date: 2026-08-27

## Verified

- Concurrent first-run setup has exactly one winner.
- Browser sessions are random, HttpOnly, SameSite Strict, seven-day credentials,
  capped at eight; the oldest session is evicted at the cap.
- Sessions are intentionally memory-only, so restart revokes all sessions.
- Password changes require the current password, revoke every existing session
  and issue a fresh current session.
- Login failures are rate-limited per direct client with bounded tracking state.
- Public auth state does not expose the configured Google email or client ID.
- TOTP login codes are single-use during their validity window; enrollment is
  session-bound and expires after ten minutes.
- Google OAuth state is single-use, ten-minute, bounded to 128 outstanding
  entries, tied to the original redirect and protected with PKCE S256.

## Focused evidence

`internal/app/auth_hardening_test.go` covers setup races, session eviction and
rotation, public-state minimization, TOTP replay, enrollment expiry, OAuth state
and PKCE, and bounded login throttling. Full tests, race tests and vet passed.
