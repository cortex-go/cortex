# CX03 evidence - CSRF, origins and proxy trust

Date: 2026-08-27

## Verified

- Every session receives an independent random CSRF token. Authenticated
  mutations require exactly one matching `X-Cortex-CSRF` header and a valid
  same-origin `Origin`.
- Public setup and login mutations also require same-origin requests, preventing
  cross-site setup/login submission.
- Origin parsing requires exactly one origin with matching scheme and host and
  rejects userinfo, paths, queries, fragments and duplicates.
- Forwarded scheme/client identity is disabled by default. `--trust-proxy`
  enables it only for a direct loopback peer; ambiguous chains fail closed.
- `--public-origin` validates the canonical external scheme and Host.
- The browser automatically attaches CSRF credentials to all mutations,
  including streamed agent starts.

## Focused evidence

`internal/app/proxy_csrf_hardening_test.go` covers explicit trust, hostile direct
clients, ambiguous forwarding chains, host/origin shapes, missing/duplicate CSRF
tokens, successful same-origin mutation and cross-site login rejection.
